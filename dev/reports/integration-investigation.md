# Integration investigation: accepted web pages, server, and package

Status: read-only investigation for a future integration gauntlet. This file is local/ignored evidence, not a product dependency or durable specification.

## Observed boundaries

- `AppShell` already owns the sole `SnapshotProvider`, theme, navigation, loading/error/retry behavior, and React Router. Its four product routes still render placeholders.
- Accepted page exports are `CurrentPage` and `RoadmapPage` from `src/web/current-roadmap`, `HistoryPage` from `src/web/history`, and `MilestoneDetailPage` from `src/web/detail`.
- Vite emits a conventional external-script/external-style application to `dist/web` (`/assets/*`); it does not require inline scripts.
- Fastify currently serves only `/api/snapshot` and evidence preview/raw routes. The global evidence-oriented CSP (`script-src 'none'; style-src 'none'; sandbox`) correctly prevents active preview content but cannot run the application.
- The web source contains two CSP-relevant inline style writes: `theme.tsx` assigns `document.documentElement.style.colorScheme`, and Roadmap assigns `--roadmap-depth` through React `style`. A strict application `style-src 'self'` will reject both. Browser verification must also detect any runtime inline style generated by the diff dependency.
- `chronicle` points to `dist/src/cli/bin.js`; runtime schemas are present in `dist/schema/v1`; `startChronicleServer` is loopback-only and supports port `0`.
- The root TypeScript build currently emits tests to `dist`; Vite has `emptyOutDir: false`; neither build cleans `dist`. Stale compiled files therefore survive renames and can be shipped.
- `npm pack --dry-run --json` currently reports 296 entries, 2,432,415 packed bytes and 3,222,377 unpacked bytes. It includes `src`, `tests`, examples, docs/design assets, visual snapshots, `test-results`, build configuration, and stale/partial compiled web/test output. NPM also reports `.gitignore` fallback because no explicit package allow-list exists.

## Minimal atomic integration contract

### Purpose

Produce one installable local Chronicle application in which the accepted views share one immutable snapshot, deep links work through Fastify, API/evidence security behavior is preserved, and an installed tarball runs from an unrelated directory without source or development files.

### Inputs and outputs

Inputs are the accepted page exports, existing `/api/*` routes, Vite `dist/web`, CLI `serve`, and runtime schema assets. Output is one deterministic build/tarball whose `chronicle serve <dataset>` serves both UI and API on loopback.

### Required behavior

1. **Atomic route wiring.** In the existing shell, replace only the four placeholders: `/` -> `CurrentPage`, `/history` -> `HistoryPage`, `/roadmap` -> `RoadmapPage`, `/milestones/:milestoneId` -> `MilestoneDetailPage`. Remove the milestone placeholder/use of `useParams`; retain a minimal not-found route. Do not add another provider, fetch, router, or view-specific state store. Navigation among all routes must retain one snapshot fetch.
2. **Static and SPA serving.** Use a maintained Fastify 5-compatible static plugin (recommended: `@fastify/static` 8.x) rather than custom path/encoding logic. Resolve the installed web root relative to compiled server code (`dist/src/server` -> `dist/web`), not the caller's working directory. `startChronicleServer` must fail early with a useful error if built assets are missing. Permit an injectable web root/API-only mode in `createChronicleServer` so server unit tests remain isolated and deterministic.
3. **Routing precedence.** Serve hashed assets with correct MIME types and `nosniff`. For non-API `GET`/`HEAD` paths that are not real assets, return `index.html` so direct milestone/history reloads work. Missing assets and all unknown `/api/*` routes remain 404 responses, never SPA HTML. Reject traversal and do not disclose absolute paths.
4. **Route-specific security.** Keep the current restrictive policy for API responses and especially evidence preview HTML. Use a separate application policy: `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. Do not apply `sandbox` to the app document. Preserve `X-Content-Type-Options`, `X-Frame-Options`, and `Referrer-Policy`. Prefer `no-store` for the HTML/snapshot; immutable caching is allowed only for fingerprinted assets after a test proves filenames are content-addressed.
5. **No unsafe-inline shortcut.** Move theme `color-scheme` into external global CSS keyed by `data-theme`. Replace Roadmap's inline depth custom property with CSP-compatible markup/CSS (prefer semantically nested lists; if a bounded class/data-selector approach is chosen, its supported depth and overflow behavior must be explicit and tested). Do not add `'unsafe-inline'` merely to make the CSP pass. Run the actual diff view under CSP because third-party runtime behavior cannot be established by source grep alone.
6. **Clean, explicit package.** Clean the exact resolved `dist` directory before every production build using a small cross-platform script with a target guard. Build backend/runtime output and Vite output from that clean state. Prefer a production TypeScript config that excludes tests and `src/web/**`; `tsconfig.web.json` remains the web type-check boundary. Add an explicit `package.json` `files` allow-list containing only runtime `dist`, `README.md`, and a license if present; keep the existing `bin`. Do not rely on `.gitignore`/`.npmignore` deny-lists. The package must include `dist/web`, `dist/schema/v1`, CLI/server/data/domain/timeline runtime JS, and all production dependencies, but no source, tests, examples, docs/design image, snapshots, reports, or test results.

### Interfaces and failure behavior

- `createChronicleServer(rootPath, { webRoot? })` (exact naming may follow existing style): omitted web root means API-only test server; a supplied invalid root produces a deterministic setup error.
- `startChronicleServer` supplies the packaged `dist/web` root and retains loopback-only binding and port validation.
- Static-handler failures use controlled 404/500 bodies and never reveal filesystem paths. API validation/evidence errors and response shapes remain unchanged.
- Vite assets are part of the package contract; `serve` must not silently fall back to an API-only process in an installed package.

### Non-goals

No changes to page data models, accepted page UX, timeline layout, schema, authoring, remote hosting, service workers, CDN caching, authentication, or development-server proxy behavior.

## Exact edit ownership and sequencing

This is an integration component and should be developed atomically by one integration agent; splitting it risks contradictory CSP and package behavior. Its exclusive tracked edit set should be declared before work:

- Route/CSP compatibility: `src/web/app-shell/app-shell.tsx`, `src/web/app-shell/theme.tsx`, `src/web/styles/global.css`, the smallest Roadmap TSX/CSS change required to remove inline style, and integration route tests only. Do not otherwise alter accepted pages.
- Static boundary: one new `src/server/static-web.ts` if useful, plus minimal edits to `src/server/server.ts`, `src/server/security.ts`, `src/server/index.ts`, and dedicated server/static tests. Do not alter existing API semantics.
- Build/package boundary: `package.json`, lockfile, one guarded clean script, optionally `tsconfig.build.json` plus minimal root config/script changes, and package smoke tests/scripts. This agent is the sole package-file editor for the round.
- Browser/package fixtures belong under a new integration-test directory, not under accepted component test directories.

All three groups are logically testable separately but merge as one submission because the application CSP depends on final markup, server startup depends on built assets, and clean-install proof depends on both. The independent integration critic remains read-only.

## Required tests and evidence

1. **Route integration:** representative canonical snapshot; direct and client-side navigation to all four routes; accepted page identity/content; valid and unknown milestone; 404; fetch count remains exactly one through navigation; retry still replaces the snapshot only when explicitly requested.
2. **Server/static:** root and deep-link SPA responses; `HEAD`; asset MIME; missing asset 404; encoded traversal rejection; unknown `/api/x` remains JSON/404; API routes win over fallback; no absolute-path leakage; route-specific CSP/header assertions; evidence preview/raw regression suite unchanged.
3. **Clean build:** seed a harmless sentinel in `dist`, run production build, prove it is removed, then prove all required runtime files exist and no compiled tests/stale renamed modules remain.
4. **Tarball allow-list:** inspect `npm pack --json`; assert only declared runtime/docs files, executable bin target present, `dist/web/index.html` and referenced assets present, runtime schemas present, and forbidden top-level source/test/example/report/config paths absent.
5. **Clean-install smoke:** create an ignored temporary consumer, install the produced tarball with production dependencies only, run its installed `chronicle` binary from that unrelated cwd, `init` and `validate` a dataset, then serve canonical data on loopback port `0`. Parse the reported origin and verify UI routes, a real asset, `/api/snapshot`, and evidence routes. Assert no dev-dependency resolution is required.
6. **Actual browser:** use packaged Fastify, not Vite, and exercise `/`, History, Roadmap, direct milestone deep-link/reload, light/dark theme, a real diff, and evidence navigation. Capture console/page errors and CSP violations; expected count is zero. Confirm the snapshot body exposes no Chronicle root path.
7. **Full gate:** schema drift/check, clean build, all unit/component/integration tests, visual tests, tarball inspection, and clean-install smoke pass from a clean checkout-equivalent state.

### Acceptance evidence format

Record exact Node/npm versions, dependency/plugin version, clean-build command/result, test counts, tarball entry count/size and forbidden-path assertion, clean-install commands/result, served URLs/statuses/headers, browser routes exercised, console/CSP count, critic verdict, and known limitations. Temporary tarballs, installs, logs, and screenshots stay under ignored `dev/evidence`, `dev/runs`, or `dev/scratch`.

## Critic focus

REJECT for any second snapshot fetch, SPA fallback swallowing `/api`/missing assets, weakening evidence-preview CSP, `'unsafe-inline'` without evidence, absolute path exposure, custom static path handling with traversal gaps, startup succeeding without UI assets, tarball dependence on repository cwd/source/dev dependencies, stale `dist` surviving the build, or a package allow-list that omits schemas/web assets. ACCEPT only after a real packed-and-installed CLI/browser run, not from Vite or repository-local execution alone.
