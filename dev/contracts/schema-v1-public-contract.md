# Contract: schema-v1-public-contract

Purpose: define the minimal public Chronicle v1 data contract before runtime tooling.

Inputs: approved corrected implementation plan and canonical History reference.

Output: tracked `docs/schema/v1-public-contract.md` covering project, branch, milestone, current state, roadmap, evidence, engineering event, revision, required/optional fields, IDs, timestamps, statuses, relations, evidence sources, revisions, branch membership, and representative YAML.

Non-goals: executable JSON Schema, TypeScript generation, validation runtime, filesystem loading, graph validation, CLI, server, or UI.

Acceptance: every explicit v1 scenario is representable; every field maps to a requirement; history/roadmap remain distinct; current and branch identity are explicit; revisions preserve conclusions; evidence can reference ground truth; engineering events remain subordinate; developer and critic accept.
